# AGENT_PROMPTS — How This Repository Was Built

This repository was developed in a pair-programming style with an AI coding agent (ZCode).
This file records the directives given to the agent during development — rewritten in a
clean, structured form — so that anyone can understand how the project evolved, verify the
work, or continue it with an agent of their own.

Each directive below is followed by a short note on what was actually delivered.

---

## Phase 1 — Review & Repair (Java implementation)

**Directive 1 — Audit the project against the course specification.**

> This repository contains an Advanced Programming (AP) course project: a university
> library management system written in Java. Review every source file and compare the
> implementation against the official requirements sheet (four user roles: Guest,
> Student, Employee, Manager). Report every defect, missing feature and spec violation,
> ordered by severity. Do not fix anything yet — analysis only.

*Outcome:* a full defect report — manager menu unreachable, main-menu Exit broken, the
book pick-up / return step disconnected from the menus, student report lookups broken,
late returns never counted, statistics classes never wired to the menus, mislabeled
menus, and more.

**Directive 2 — Fix the defects according to the reference and good coding practices.**

> Implement the fixes exactly according to the reference specification and standard
> coding practices. Keep the existing architecture, follow the spec precisely, remove
> dead code, and verify every change by compiling and running scripted end-to-end tests.

*Outcome:* 17 of 24 source files fixed; the full borrow cycle (request → approval →
pick-up → return) works; activation/deactivation, statistics and employee performance
are wired to the menus; five scripted scenarios pass end to end.

---

## Phase 2 — Verification

**Directive 3 — Run the project inside the IDE.**

> Open the project in IntelliJ IDEA, make it build cleanly, run the application and

## Phase 3 — Publishing to GitHub

**Directive 4 — Create a GitHub repository and prepare the local project.**

> Create a repository on my GitHub account for this project and prepare a local Git

*Outcome:* the local `SE` repository on branch `main` with an English README, `.gitignore`
and IntelliJ module configuration (`src` marked as the source root).

**Directive 5 — Fill the cloned repository and publish it.**

> I have created the repository and cloned it. Put the corrected sources inside it,

*Outcome:* 24 fixed source files under `src/ap/projects/finalproject/` pushed to
[`ArianShayestehfard/SE`](https://github.com/ArianShayestehfard/SE).

## Phase 4 — Second Implementation (Python) & Documentation

**Directive 6 — Port the system to Python and rewrite the README in English.**

> Add a Python version of the same system to this repository, with the same behavior as
> the Java version, and rewrite the README entirely in English.

*Outcome:* `python/library_system.py` — a standard-library-only implementation mirroring
every rule of the Java version — plus a fully English README covering both versions.

**Directive 7 — Document the architecture visually.**

> Build an architecture diagram for this system and display it in the README.

*Outcome:* `docs/architecture.svg` (rendered in the README, editable source in
`docs/architecture.excalidraw`) generated by `tools/gen_architecture.py`.

**Directive 8 — Add SQLite storage to the Python version; keep the commit history standard and substantial.**

> Add a SQLite database to the Python version so all data is stored in the database.
> Structure the work as standard, well-formed commits — and do not make them too few.

*Outcome:* a dedicated `python/database.py` layer (schema + seeding), every manager
migrated to parameterized SQL, JSON storage removed, a 22-check end-to-end test
(`tools/test_python_sqlite.py`), and seven Conventional Commits
(`feat` / `refactor` ×4 / `test` / `docs`).

**Directive 9 — Add a Mermaid data-flow diagram and complete the repository metadata.**

> Create a Mermaid data-flow diagram specific to this system — in the same style as a
> reference example — place it in the README, and fill in the repository's About
> section: description and topics.

*Outcome:* the Mermaid diagram in the Architecture section (rendered natively by
GitHub), a repository description, and seven topics
(`java`, `python`, `sqlite3-database`, `library-management-system`, `console-application`,
`university-project`, `student-project`).
